## Decision for the next study

Do not launch another broad checklist batch or claim the model is categorically unable to generate executable programs. The unresolved question is whether a specific prompt strategy can adapt a long-running historical design to the registered work budget while preserving useful optimization behavior.

A next protocol should retain the seven frozen parents and explicitly compare the current checklist with a precise bounded-work adaptation prompt. The latter must state a researcher-chosen computational structure and disclose that this constrains design freedom; it is not autonomous algorithm discovery. Freeze any numeric work limits before generation and check compliance separately from geometry and score. Preserve all original candidates and failures. Do not silently shorten historical code or increase execution time.

An alternative is to change the runtime budget, but that is a different scientific question and requires a separately registered condition and a comparable baseline. Avoid changing model, parent pools, prompt structure and evaluation budget together.

Before selecting a new numeric work limit, perform a separately labelled evaluator calibration using prepared code only, with no LLM calls and no claims of generated discoveries. The calibration should check the exact evaluator startup cost and runtime of a known executable reference in the current deployment. This must not be pooled with historical scores from other environments. Reuse a current-deployment calibration if one already exists; inspect its source hash, environment and timing record first.

The two completed generation conditions remain the current results. No new experiment is registered or running as a result of this audit. This audit revises the proposed generic capability diagnostic in light of existing evidence rather than duplicating it.
